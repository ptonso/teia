# 2026-10-09

Plugin model added to the skill, after a long design session on how teia, private and public plugins, research projects and baselines relate.

- The user's model: every research project is a teia plugin, the single source of truth for its contribution. Other projects reuse it by installing it, never by copying it. Code that does not speak teia is wrapped once. Teia is one package with a stable language (base, core), frozen-once-released task contracts, and a growing zoo.
- Ownership is visible in names: the plugin's own Python package, and an owner folder named after the package in every config path (`netmodule=<task>/<package>/<name>`). The user agreed to mirroring teia's layout; the owner folder was my recommendation and is enforced by `teia plugin check`.
- Baselines: three ways (trained, frozen, imported), cheapest that keeps equal what the claim is about. Verified in a sandbox that a frozen baseline works today: a netmodule with no loss node runs with `epochs=0` (fit skipped, test and eval still run). There is no importer for saved predictions; the guide says so instead of inventing one.
- Licenses: copyleft code never enters teia; it lives in a wrapper plugin with the same license. The user chose Apache-2.0 for teia.
- New guides make-a-plugin, baselines, publish. inspect, write-config and write-component now place files in `src/<package>/` with owner folders; the old advice (a package in the project root resolving without install) is gone, since a plugin is installed editable.
- `teia plugin init` was added so the agent scaffolds deterministically instead of hand-writing pyproject and the search-path file.
- Skills of installed plugins are now linked by `teia init`, so a plugin can ship its own skill to the projects that install it.

## Agent test, same day

Three Sonnet agents ran the skills cold in isolated sandboxes: make a plain project a plugin, add a frozen scikit-learn baseline, publish a project that borrowed an encoder from a private plugin. All three succeeded; the runs exposed:

- A frozen model with no trainable parameter crashed in optimizer construction under `epochs=0`; the agent worked around it with a placeholder parameter. Fixed in the engine (no optimizer when nothing trains; an error if epochs > 0), and the guide now says so.
- An agent named its preset after the dataset (`digits.yaml`). The layout already said `<task>.yaml`; the move step now says it explicitly, and the checker has a `task-name` rule.
- An agent reported the dataset held two classes, from a partial listing; it held ten. The report rule now asks for how each claim about data or results was checked.
- An agent skipped `Upstream` for the user's own saved model, which is right; the guide now separates the user's artifacts from upstream code.
- Setting up the publish scenario showed the `provider` rule missed leaves mounted from another package; it now reads composed configs.
