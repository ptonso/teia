# 2026-10-10

The owner folder is gone. While using teia inside a project, the user questioned why plugin configs carried the package name (`conf/**/teia_lab/*.yaml`) and decided that every conf tree, teia core, teia, arsenal, plugins and the project, has the same structure.

- Deduplication moved to runtime. After composition, every option the run selects (task, modules, mounted leaves, system groups) is looked up in every layer, and a path found in more than one stops the run with the path and both providers. Measured cost: a few file lookups, against about 300 ms per compose. The user chose selected options only, so a clash on an option nobody uses does not block runs; `teia config lint` reports every duplicate as `duplicate`, and `teia plugin check` turns one in the plugin's files into an error.
- A project file at the path of an installed option used to be silently ignored; it now fails the run. The ground rule says so.
- One preset per task across all packages, the user's choice. A plugin adds modules to an installed task and is run with `task=<task> netmodule=<task>/<name>`; it ships a preset only for a task it introduces. teia-lab already worked this way: its baselines are selections on top of the task preset.
- The checker lost `conf-owner` and `conf-duplicate` (now the lint `duplicate` finding). make-a-plugin, write-config, write-component, baselines and the ground rules no longer mention the owner folder, and advise descriptive names (`resnet18_imagenet`) since names are shared by every installed package.
